## 集成测试覆盖

1. 未登录请求返回 401。
2. 正确密码建立会话，错误密码被拒绝，退出使会话失效。
3. 修改请求必须携带 CSRF token。
4. 跨企业读取、写入、辅助检索均被拒绝，列表不泄露其他企业数据。
5. 同企业客户只能读写自己的工单。
6. 客户不能分配、流转、创建知识或使用员工回复辅助；看不到草稿。
7. 非法状态跳转不改变数据与审计。
8. 旧版本返回 409，不额外生成审计事件。
9. 两线程竞争同一版本，恰好一个成功、一个冲突，只产生一次变更审计。
10. 不能把负责人设为其他企业用户或客户。
11. 已关闭工单拒绝回复与分配。
12. 演示回复只引用当前企业已发布知识；无相关证据时返回空草稿。
13. 非法输入、分页越界与 SQL 注入样例被正确处理。

## 本地工具限制与验证方式

当前受限 Windows 执行环境下，系统 javac 的 ZipFS 真实路径解析在项目父目录触发 AccessDenied；常规 Maven 编译流程未在该环境通过。没有将它算作构建成功。

为完成源码验证，使用 Eclipse ECJ 3.36.0 的 Java 17 模式直接编译相同的主源码与测试源码，再用 JUnit Platform Console 1.12.2 执行上述测试；Spring 仍使用真正的 WebApplicationContext、Spring Security、Flyway 和 H2。不是替换业务实现或跳过测试。

仓库中的 `scripts/check-portable.ps1` 提供此流程；验证工具下载后会核对固定 SHA-256。

前端生产构建和 Maven jar 打包 / Spring Boot repackage 均成功。原生 Windows 路径问题不影响已打包应用的启动验证。仓库 CI 仍使用常规 Maven + javac，需要在 GitHub 连接后实际运行；目前没有将 CI 描述为已通过。
