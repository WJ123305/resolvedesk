# 后续实施顺序

当前里程碑：0.1，本地工单业务闭环。

## 0.2：知识生命周期与可靠任务

1. 为文章加入编辑、不可变版本记录、发布/撤回操作及知识审计。
2. 用事务内任务记录保证文章发布与索引任务创建一致。
3. Worker 使用租约领取任务，有限次重试，失败可观察；唯一业务键与版本校验实现幂等。
4. 覆盖重复投递、处理中断、过期任务恢复、更新删除后的旧索引不可见。
5. 加入 PostgreSQL Testcontainers 回归测试，验证实际数据库行为。

## 0.3：可评估的 AI

1. 建立 60 条带期望知识来源的问题集，并划分开发集/保留测试集。
2. 接入 pgvector 与嵌入接口，保留当前关键词方案作为基线。
3. 实现真实模型适配器、超时、用量记录、证据不足处理。
4. 结构化引用只接受检索到的、当前企业已发布文章 ID；防止文档内容覆盖系统规则。
5. 输出检索命中、引用正确性、无答案处理和越权测试结果，不预先承诺目标准确率。

## 0.4：工程化和求职交付

1. 十万条工单生成脚本、固定硬件与并发参数的压测，记录 P50/P95 和错误率。
2. 针对真实慢查询做 EXPLAIN 分析和索引优化，保留前后数据。
3. 账号管理、限流、部署配置、备份及恢复演练、日志和基础监控。
4. 端到端自动化测试、录制演示视频、整理面试问答和基于实测的简历描述。

## 首次练习建议

先理解“创建工单 → 状态变化 → 审计记录”的数据链路，再能解释版本冲突为什么返回 409。后续尝试独立增加一个筛选字段，并从前端、接口到 SQL 完成小改动。
